# 数据导入模式说明

## 两种检查模式对比

### 1. 快速模式 (Fast Mode) - 默认

**检查策略：**
- 只检查CSV文件的**首尾两条记录**是否存在于数据库
- 如果首尾都存在 → 认为整个文件完整，直接跳过
- 如果首尾都不存在 → 认为文件完全缺失，直接批量插入
- 如果只有部分存在 → 自动切换到详细模式

**优点：**
- ⚡ **速度极快**：每个文件只需查询2次数据库
- 💰 **资源节约**：大幅减少数据库查询和网络传输
- ✅ **适合大批量**：导入3000+文件时推荐使用

**适用场景：**
- 正常的批量数据导入
- 数据已基本完整，只是补充缺失部分
- 定期更新最新数据

**性能对比：**
```
3290个M1文件导入：
- 快速模式：约 5-10 分钟
- 详细模式：约 30-60 分钟
```

---

### 2. 详细模式 (Comprehensive Mode)

**检查策略：**
- 检查CSV文件中的**每一条记录**是否存在于数据库
- 逐条比对，确保数据100%准确
- 可以检测中间缺失的数据

**优点：**
- 🔍 **精确无误**：确保每条数据都被验证
- 🛠️ **适合修复**：能发现并补充中间缺失的数据
- ✅ **完全可靠**：适合严格的数据质量要求

**适用场景：**
- 怀疑某个文件数据不完整
- 数据导入后需要精确验证
- 修复已知的数据问题
- 审计或合规要求

## 使用方法

### 方法一：一键导入（快速模式）

```powershell
python 一键导入所有数据.py
```

- ✅ 默认使用**快速模式**
- ✅ 自动处理所有文件
- ✅ 生成导入日志

### 方法二：严格校验（详细模式）

```powershell
python 严格校验导入数据.py
```

**交互式操作流程：**

1. 选择时间周期（D1/M1）
2. 选择货币对（AUDUSD, EURUSD等）
3. 选择具体文件：
   - **D1**：选择年份或全部
   - **M1**：选择年份 → 选择周（单周/范围/全部）
4. 确认后开始详细检查

**示例：检查 EURUSD 2020年 第1-10周**
```
步骤1: 选择 M1
步骤2: 选择 EURUSD
步骤3: 选择 2020
步骤4: 输入 1-10
```

## 模式切换规则

### 自动降级机制

快速模式检测到问题时会**自动切换**到详细模式：

```
[快速检测] → 发现首尾记录不一致
    ↓
自动切换到详细模式
    ↓
逐条检查并导入缺失数据
```

**触发条件：**
- 文件首记录存在，尾记录不存在
- 文件尾记录存在，首记录不存在

## 常见问题

### Q1: 什么时候用快速模式？
**A:** 绝大多数情况都用快速模式。只有发现数据问题时才用详细模式。

### Q2: 快速模式会漏掉中间的数据吗？
**A:** 
- **正常情况**：不会。因为数据是按时间顺序连续的
- **异常情况**：如果中间有缺失，快速模式检测不到
- **解决方案**：定期使用验证工具检查，发现问题后用详细模式修复

### Q3: 如何知道是否需要详细模式？
**A:** 运行验证工具：
```powershell
python 一键验证所有数据.py
```
如果评分低于A或发现缺失，再用详细模式针对性修复。

### Q4: 能否强制所有文件使用详细模式？
**A:** 可以，但不推荐。如果确实需要：
1. 修改 `一键导入所有数据.py` 第117行
2. 将 `check_mode='fast'` 改为 `check_mode='comprehensive'`

### Q5: 详细模式会覆盖已有数据吗？
**A:** 不会。详细模式只会：
- 跳过已存在且一致的数据
- 插入缺失的数据
- 询问是否覆盖冲突的数据

## 最佳实践

```

  4. 再次运行验证工具确认
```

## 技术细节

### 快速模式实现

```python
# 只查询首尾两条记录
SELECT COUNT(*) FROM table
WHERE symbol = 'EURUSD'
  AND timestamp IN ('2020-01-01 00:00:00', '2020-01-07 23:59:00')
```

### 详细模式实现

```python
# 查询整个时间范围的所有记录
SELECT timestamp, open, high, low, close
FROM table
WHERE symbol = 'EURUSD'
  AND timestamp >= '2020-01-01 00:00:00'
  AND timestamp <= '2020-01-07 23:59:00'
ORDER BY timestamp
```
